# iOS（iPhone / iPad）部署说明

XLerp 本身是**纯网页应用**，服务端跑在任何 Docker / Node.js 机器上，iOS 端不需要单独编译 App 就能用。

## 方式一：Safari 添加到主屏幕（推荐，无需签名）

1. iPhone / iPad 连上和服务端同一个 Wi-Fi
2. Safari 打开 `http://服务器IP:8686`
3. 点底部 **分享** → **添加到主屏幕**
4. 桌面会出现 XLerp 图标，点开是全屏无地址栏的体验，和原生 App 几乎无差别

优点：不需要 Apple 开发者账号、不需要签名、服务端升级后 iOS 端自动更新。

## 方式二：自签名 IPA（需要开发者账号）

仓库里的 Android 客户端（`android/`）是 Java 写的原生壳，**不能直接复用到 iOS**。要做原生 iOS 壳需要：

- 一个 WKWebView 容器的 Xcode 工程（约 100 行 Swift）
- 免费 Apple ID 只能 7 天签名，需重新签
- 上架 App Store 需要 Apple Developer Program（$99/年）和审核

对于内部使用，**方式一完全够用**，而且省掉了审核和签名续期。

## 方式三：PWA 离线缓存

服务端已带 `manifest` 和图标，Safari 添加到主屏幕后支持基本离线缓存（界面壳），数据仍需连服务器。

## 局域网 HTTPS 说明

iOS Safari 对 `http://` 地址的「添加到主屏幕」支持正常，但如果要用摄像头扫码等能力，需要 `https://`：

- 用反向代理（Caddy / Nginx）套一层自签证书
- 或让 NAS 自带的证书服务（群晖、飞牛都内置换证书功能）

## 已支持的移动端能力

| 功能 | iOS Safari | 说明 |
|---|---|---|
| 开单、收货、发货 | ✅ | 完整支持 |
| 扫码（摄像头） | ⚠️ | 需 https，或用手机相机扫完手输 |
| 打印单据 | ✅ | 走系统打印 / 存 PDF |
| 导出 CSV | ✅ | 走系统分享 |
| 离线壳 | ✅ | 需先添加到主屏幕 |

## 建议做法

**内部使用就用方式一（添加到主屏幕）**。这是最稳的路子：
- 零成本
- 服务端升级后手机端界面自动更新，不用重装
- 断网时界面壳还在，重连后数据自动同步

如果确实需要 App Store 上架，再单独做 Xcode 工程，那部分工作量约 2-3 天（含审核材料）。
